# MVP 核心模块评测报告（2026-09-29）

目标：每个核心模块在**验收集**上的准确率 ≥ 80%。
标准答案由用户在工作台的 `/eval` 标注页逐条标注。样本按 id 哈希固定分为调优集（约 2/3）和验收集（约 1/3）：调提示词和规则时只看调优集，验收集在代码冻结后才标注，用来判定是否达标。

## 结果

| 模块 | 评什么（一条样本） | 调优集 | 验收集 | 验收集 95% 置信下限 | 达标 |
|---|---|---|---|---|---|
| JD 抓取 | 抓到的 JD 是否是这家公司、这个岗位、这一届 | 100%（18/18） | 100%（5/5） | 57% | ✓ |
| 岗位匹配 | 匹配理由的证据是否真的支持该要求；差距是否真的缺 | 89%（42/47） | 83%（15/18） | 61% | ✓ |
| 检索 | 按 JD 挑出的前 8 条素材是否相关 | 92%（24/26） | 93%（13/14） | 69% | ✓ |
| 定制简历 | 每条 bullet 直接用 / 小改能用算对；编造数字自动算错 | 97%（35/36） | 95%（21/22） | 78% | ✓ |
| 插件填表 | 演示表单（Moka、北森、飞书、飞书 formily 等）上的自动化测试用例 | 97%（37/38） | 100%（15/15） | 80% | ✓ |

JD 抓取的覆盖率（抓得到 JD 的岗位占比）单独统计：23/30 = 77%，不计入准确率。

**注意样本量**：验收集每个模块只有 5~22 条，置信下限普遍低于 80%。“达标”指标注出来的比例 ≥80%，还不能算统计上的确定结论；后续需要在日常使用中继续积累标注。

非核心模块（邮件识别、面试准备稿）已经跑过基线，但按决定这次不标注、不计入结论。

## 这次迭代改了什么

- **定制简历 72% → 97%（调优集）**
  - 基线的错误几乎都是“经历跟岗位不相关”。修改后，挑经历按用户定的优先级：业务相关度 → 岗位相关度 → 行业相关度，同等条件下大厂经历优先；学术经历（论文）只用在 AI 强相关岗位。生成前会给每段经历标注「大厂 / 职能 / 学术」和 JD 文本相似度，相似度只作参考。
  - 数字核对原来会误报：依据写“五种”、bullet 写“5 种”也会被判为编造。现在依据一侧会把中文数字转成阿拉伯数字再比对。
- **检索**：JD 按要点拆开多路查询，同时按关键词打分并和向量排名合并；每段经历设条数上限；近似重复的素材只留一条；过滤掉岗位名、学历门槛、小标题这类不构成要点的行。
- **长输出截断**：`deepseek-flash` 是推理模型，思考用的 token 也计入 `max_tokens`。长输出统一用 `LONG_OUTPUT = 32768`，超时放宽到 5 分钟。

## 剩下的典型错误

- **岗位匹配（验收集 3 条）**：理由引用的证据太牵强，例如用论文里的 AI 绘图审计去对应“影像审美”，或者只引用了一份资料的标题。
- **检索、简历（各 1 条）**：影像类岗位仍然会挑到咨询公司的汽车座舱调研，属于业务不相关。

## 怎么重跑

- **页面**：`/eval`，点某个模块的「重跑」。
- **命令行**：`node --conditions=react-server --env-file=.env.local --import tsx scripts/eval.ts [模块…]`
  - 模块：`jd` `match` `retrieval` `resume` `plugin`；非核心：`mail` `prep`
  - 不带模块名时只打印当前成绩。

重跑后，已标注的样本会沿用标注。生成类模块（简历、准备稿）的文字一旦变了，这条样本就需要重新标注。评测数据保存在 `data/eval/`，只在本机，不会提交到仓库。
