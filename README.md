# SwipeApply · 求职工作台

打开首页像刷 Tinder 一样刷新岗位：右滑进入投递工作台，AI 按 JD 用你的经历卡片定制简历，你用语音或文字让它改；投完记进「我的投递」，回来接着刷。**所有数据只存在你电脑上的 `data/` 文件夹里。**

> **English** — SwipeApply is a local-first job-hunting workbench for campus recruiting in China. Swipe through job cards; AI matches roles to your experience, tailors a one-page A4 resume to each JD (every line traceable to your own materials, no invented numbers), and a browser extension autofills application forms (Feishu Hire, Moka, Beisen). Everything runs on your own machine — no server, your data stays in `data/`. Bring your own LLM keys (DeepSeek / Qwen or any OpenAI-compatible API).

**能做什么**

- **刷岗位**：右滑投递、左滑跳过，AI 从你的选择里学偏好（左滑会问为什么，按「整车 / 硬件」这样的细分方向学，不会一棍子打死整个职能）
- **定制简历**：每个岗位按 JD 挑经历、改措辞，固定一页 A4；每一句都能追溯到你素材库里的原句，数字不在原句里的会标出来；直接在 A4 页面上改，所见即所得
- **自动填网申**：浏览器插件一键填表，不替你点提交
- **投递和面试**：读招聘邮件更新进度，面试前自动准备公司调研和面试题
- **隐私**：数据只在本机；发给模型前先在本地脱敏，你能看到发出去的全部内容

## 下载即用（不用写代码）

1. 到右边的 **[Releases](https://github.com/ashleywuu057-gif/SwipeApply/releases/latest)** 下载最新的 `SwipeApply-*.zip`，解压到一个固定的文件夹（不要在压缩包里直接双击）
2. 双击启动：
   - **Windows**：`启动 SwipeApply.bat`
   - **Mac**：`启动 SwipeApply（Mac）.command`。第一次如果提示「无法验证开发者」：右键点它 →「打开」→ 再点「打开」
3. 第一次会自动下载 Node.js 和依赖（都放在这个文件夹里，不装到系统，国内镜像，大约 5–10 分钟），然后弹出一个文本文件让你填 **两个 API Key**，保存后自动打开浏览器
4. 以后每次用，再双击一下就行。那个黑色命令行窗口别关，关了 SwipeApply 就停了

**两个 Key 怎么申请**（各几分钟，充几块钱够用一整个求职季）：

| 填在哪 | 是什么 | 去哪申请 |
| --- | --- | --- |
| `LLM_API_KEY=` | DeepSeek：写简历、改简历、匹配岗位 | [platform.deepseek.com](https://platform.deepseek.com) → 注册 → 充值 → API Keys → 创建 |
| `SEARCH_LLM_API_KEY=` | 阿里云百炼（通义千问）：联网找岗位和 JD、快速理解你说的话 | [bailian.console.aliyun.com](https://bailian.console.aliyun.com) → 开通百炼 → API-KEY → 创建 |

Key 只保存在你电脑上的 `.env.local` 里，不会上传到任何地方。不要把填好 Key 的文件夹发给别人。

## 从源码运行（开发者）

每个人在自己电脑上运行一份：**没有服务器，你的简历、素材、投递记录只存在自己电脑的 `data/` 文件夹里**，密钥也只在你自己的 `.env.local` 里。

**1. 准备**：安装 [Node.js](https://nodejs.org/) 20 或更高版本（Windows / macOS 都可以）。

**2. 下载并安装依赖**

```bash
git clone <这个仓库的地址>
cd <仓库文件夹>
npm install          # 国内网络慢可以加 --registry=https://registry.npmmirror.com
```

**3. 配置密钥**：把 `.env.example` 复制一份，改名为 `.env.local`，填**你自己的** key：

| 配置 | 必填吗 | 用来做什么 | 不填会怎样 |
| --- | --- | --- | --- |
| `LLM_API_KEY` 等 `LLM_*` | 建议填 | 解析简历、写简历、匹配岗位、模拟面试（DeepSeek、通义千问、Kimi 等兼容 OpenAI 接口的服务都行） | 只能用本地规则解析，大部分 AI 功能不可用 |
| `SEARCH_LLM_*` | 可选 | 通义千问：联网搜岗位、深度调研公司、按意思检索素材（向量检索） | 没有联网搜索；素材检索退回全部发送 |
| `MAIL_USER` / `MAIL_PASS` | 可选 | 同步招聘邮件（填邮箱**授权码**，不是登录密码） | 投递进度要手动更新 |

**4. 启动**

```bash
npm run dev
```

打开 http://localhost:3000 。只监听本机 `127.0.0.1`，同一个 Wi-Fi 下的其他设备访问不到。

**5. 可选：自动填网申的浏览器插件**

```bash
cd extension
npm ci
npm run build
```

然后在 Edge 打开 `edge://extensions`（Chrome 是 `chrome://extensions`），打开「开发人员模式」，点「加载解压缩的扩展」，选择 `extension/dist` 文件夹。

**说明**
- 用浏览器打开网页抓 JD 这个功能只在 Windows 上可用，其他功能各平台都能用。
- 发给大模型的内容会先在本地替换掉手机号、邮箱、人名等敏感信息；标了「仅本地」的经历不会发给模型。
- `data/` 和 `.env.local` 已经在 `.gitignore` 里，不会被提交。

## 岗位流 + 投递工作台（首页，新版）

**岗位流**（首页）
- 岗位来自「岗位库」（导入的表格 + 每日联网搜索），去掉已经滑过的、这家公司已经投过的、已经截止的，按匹配度排序。岗位库是空的时候显示示例岗位
- 匹配度 = 你的方向 + 和你的经历、资料对得上的点 + 学到的偏好 + 截止临近；卡片翻面看「为什么推给你」：岗位要什么 ↔ 你哪一句经历或哪份资料对得上
  - 先在本地秒出：能力关键词对经历原句；行业 / 领域词（例如岗位写"商用机器人"，你的业务知识写"具身智能"）对经历原句和素材资料
  - 卡片翻到最上面时，AI 再对照一遍（经历原句 + 资料的标题和开头，先脱敏），给出更准的理由；只能引用素材里真实存在的句子或资料，结果按岗位缓存
- 操作：拖动卡片，或键盘 ← 跳过、→ 投递、↑ 稍后再看、空格翻面、Z 撤回
- **从滑动里学习（长期记忆）**：左滑后可以点一下理由（地点 / 方向 / 公司 / 要求），或者同一方向连续跳过、海外岗连续投递，AI 会学到一条偏好并弹出「记住了：…」，可以当场撤销；以后按这些偏好排序。右上角「AI 记住的事」里能查看、关掉、删除
- 预取：最上面两张卡片会在后台抓 JD、生成公司速览，右滑时基本是现成的

**JD 从哪来**（很多岗位链接只是公司校招首页、动态页面，或者银行官网这类证书特殊的网站，直接下载拿不到）按顺序试：
1. 直接下载网申链接的网页
2. 用你电脑上的 Edge / Chrome 在后台打开（不弹窗口，能加载动态内容）；是首页的话，顺着「这个岗位 / 校园招聘」的链接再点一层。不用另外下载浏览器；找不到 Edge / Chrome 时可以在 `.env.local` 设 `JD_BROWSER_PATH`
3. 联网搜索这个公司的这个岗位（需要 `SEARCH_LLM_API_KEY`），读搜到的官网详情页、牛客、公众号等
4. 都不行：**剪藏 JD**。把工作台 JD 栏里的「📎 剪藏 JD」拖到浏览器书签栏；在任何岗位页面（包括要登录才能看的）点它，页面文字带回工作台，选好对应岗位保存。先选中一段文字再点，就只存选中的部分。页面文字放在网址 # 后面传过来，不经过任何服务器

每一步都只从网页原文里挑句子（挑完核对都在原文里），并确认是这家公司的这个岗位；JD 栏会显示出处。找的过程在后台跑，不会卡住页面；找到后工作台会提示「按 JD 重新生成简历」。

**投递工作台**（右滑后）
- 左：公司速览——公司介绍、这个岗位所在的业务条线、主要产品、其他要点（规模、近期动态等）。配置了千问联网搜索时联网查、每条标来源编号；没配置时用模型已有知识，标「未联网核实」。按公司缓存两周。下面是 JD（自动从网申链接抓取，只挑原文句子；抓不到可以手动粘贴）
- 右：定制简历——从经历卡片里挑 2~4 段最相关的经历，每段挑 2~4 句，按 JD 调整措辞
  - **不编造（harness）**：每一句都标明依据的素材原句；改写后出现原句里没有的数字会标黄「待核对」，导出前会提醒；发给模型前先在本地脱敏，「仅本地」的经历不发
  - 教育经历固定在最上面（从简历抬头读取）；下面的经历和技能是一块块卡片，按住 ⠿ 拖动排序，拖到「备选」移出简历，备选里的经历拖回来（或点 ＋）就放进去；导出的 PDF 按卡片顺序排
  - 点句子直接改；悬停看「原句」；技能、作品集可以增删
  - 简历抬头（姓名、电话、邮箱、教育）只存在本机，不发给模型
  - 素材里找不到 JD 要求的证据时，AI 会主动问你（例如「你有游戏相关经历吗？」）
- 底部：和 agent 说话（文字或 🎙 语音）。它会自己决定调用哪些工具：
  - `search_library` 查素材库（经历原句、补充事实、复盘笔记和工作文档）
  - `rewrite_bullet` / `add_bullet` / `remove_bullet` / `set_experience` / `set_skills` 改简历——每次都过核对，不通过就驳回让它重来
  - `ask_user` 反问你；`save_fact` 把你回答的新事实记进素材库（必须是你的原话），之后可以作为依据
  - `suggest_writing_pref` 建议记住一条写作偏好（如「不用'赋能'这类词」），你点「记住」后以后都遵守；你手动改句子时也会总结偏好来问你
  - `web_search` / `read_page` / `update_brief` 查公司、改速览（配置了联网搜索时）
- 投递：导出 PDF（浏览器打印 → 另存为 PDF）→ 打开网申页，用「投简助手」插件自动填写（填不上的可以一段段复制经历描述）→ 你在官网提交后，在插件里「确认已提交」或回来点「我已提交」，记进「我的投递」（同一家公司只保留一条），回到岗位流看下一个

语音输入用浏览器自带的语音识别（Chrome / Edge），录音会发到 Google / 微软的语音服务识别；介意的话打字。

## 自动填表（投简助手插件）

浏览器插件在 `extension/`，基于开源项目 [ApplyKit](https://github.com/DeepestWind/ApplyKit)（MIT）：Moka、北森、飞书招聘有专用适配器，其他网站用通用识别。只填有把握的字段，填完回读核对；不绕过验证码，**不替你点提交**。

- **安装**（第一次）：`cd extension && npm ci && npm run build`，然后在 Edge 打开 `edge://extensions`（Chrome 是 `chrome://extensions`），打开开发人员模式，「加载解压缩的扩展」选择 `extension\dist`
- **同步履历**：在网申页点插件 →「从SwipeApply同步履历」。插件从 `localhost:3000/api/applykit/profile` 读取简历抬头、固定的教育经历、语言成绩、奖项和经历；当前网申页能对上岗位库里的岗位时，用这个岗位定制过的简历。内容没变时重复同步不会多出版本
- **填写**：「一键填写」→ 核对待处理的字段 → 你自己提交
- **回传**：在插件里「确认已提交」后，插件通知 `localhost:3000/api/applykit/submitted`：对得上岗位就和投递工作台里点「已提交」一样，对不上就按公司记一条，都算当天的有效投递
- **隐私**：插件只申请了本机SwipeApply（`localhost:3000`、`127.0.0.1:3000`）的访问权限，履历只在你电脑上的浏览器和工作台之间传
- 对 ApplyKit 的本地改动见 `extension/JOBPREP.md`

## 素材库流程

1. **上传资料**：可以附一段补充说明。飞书文档请先导出为 Word。支持的格式：
   - 文档：PDF、Word(.docx)、PPT(.pptx，按页提取，含表格和备注)、Markdown、TXT
   - 数据和代码：CSV（转成表格，最多收录 500 行）、Jupyter 笔记本 .ipynb（不收录运行输出）、.py .sql .js .ts .r .java .json .yaml .sh .html .css
   - 图片：PNG、JPG、BMP、WebP，用开源的 Tesseract 在本机识别文字（中文 + 英文），原图不外传；每张需要几秒，手写和复杂图表识别不准
2. **隐私检查**：右侧显示的就是将要发给模型的全部内容（文件名也会脱敏）。全部在本机用规则完成：
   - 自动屏蔽（可分别开关）：
     - 人名：带称呼的（张伟经理）、有上下文的（和张伟讨论、负责人：李娜）、简历抬头的本人姓名、@某人、英文名（mentor Alice）
     - 昵称：阿强、小王 / 老李、强哥 / 婷姐 / 王总、王经理、叠字（婷婷）、双字母（yy）
     - 表格和数据块：整张表格、连续多行以数字为主的内容（通常是图表数据）；带起止时间的表格版简历会保留
     - 联系方式：邮箱、手机、座机、身份证、微信
   - 在一份文件里识别出的人名，在这批所有文件里都会屏蔽
   - 敏感词：公司名、客户名、项目代号等，自己填
   - 不屏蔽的词：规则误判时，点标签上的 × 或手动填写（例如"小米"）
   - 图片不会被读取，也不会发送；数字默认保留
3. **分类与归属**：
   - 每份资料分到一类：简历 / 业务知识 / 项目复盘 / 工作源文件
   - 简历用来识别经历，生成卡片（公司 · 岗位 · 时间 · 简历原句），原文里找不到的句子会标黄
   - 其他资料整篇保留，归到一段经历下面；只分类，不改写、不总结
   - 分错了可以当场改，保存后也能在卡片详情里改
   - **自动切分**：一份文件里有不同类型的内容（比如前半是业务知识、后半是面试问答），会按标题切成小节分别分类。切开的小节首尾相接，原文一字不改、不重复；各小节分类都一样时不切。可以点按钮取消切分。
     识别的标题：Markdown 的 `#` `##` `###`、Word 的标题样式、「第一部分」「一、」「（一）」「【标题】」

卡片详情页分成「业务知识 / 项目复盘 / 工作源文件」三栏，点文件名展开原文。不属于具体经历的资料（比如 AI 基础概念）放在首页的「通用资料」里。

## 投递看板（P2）

**岗位库**（左侧「岗位库」）
- 导入大家共享的秋招汇总表：飞书、腾讯文档导出为 Excel(.xlsx) 或 CSV 即可。自动找表头，识别公司、岗位、地点、截止时间、网申链接、届别、行业、内推码等列；合并单元格（公司只写一次）也能处理；重复岗位不会重复导入
- 岗位名自动归到 9 个方向（产品、运营、市场/品牌、战略/分析、技术、设计、销售/商务、职能、其他），并标出海外相关岗位
- 选好「我的方向」后默认只看这些方向；可以只看收藏、隐藏已截止；3 天内截止的标红
- 投完点「我已投递」，岗位进入投递进度
- **每日自动更新**：项目开着时，每天到点（默认 9:00，可改）自动拉取「订阅源」，新岗位直接入库并标「新」；到点时电脑没开，下次打开项目会补跑一次。也可以随时点「立即更新」
  - 订阅源要是公开可下载的表格：CSV、Excel、Markdown 表格（GitHub 页面链接会自动转成原始文件）、网页表格
  - 腾讯文档、飞书等需要登录的链接读不到，请导出 Excel 后手动导入
  - **校招公司清单（jobworthy）**：同步开源项目 [jobworthy](https://github.com/wlunan/jobworthy)（Apache-2.0）每天汇总的 1800 多家公司校招入口，按「我的方向」筛选、跳过已投公司。每条是一家公司（招聘方向 + 官方校招入口），点「去官网搜」在官网找岗位，找到后点「＋贴岗位链接」贴回来，作为一条具体岗位入库。官网是飞书招聘（包括字节）的，会用「在官网找岗位的关键词」（默认从经历卡片的岗位名里取）调它的职位搜索接口，自动列出具体的校招正式岗位和详情页。国内直连 GitHub 常超时，数据先从项目网站和 jsDelivr 镜像下载
  - **行业**：按公司名和行业、岗位关键词分成互联网、AI、出海、外企、金融、制造/硬件、快消/零售、其他；「我的行业」默认是互联网、AI、出海、外企，可以只看这些
  - **千问联网搜索（默认关）**：按「我的方向」（最多 4 个）联网搜索正在开放网申的秋招岗位，只收有网申链接的，来源标「联网搜索」。单独用一个带联网搜索的模型，和简历解析等功能用的模型分开配置：在 `.env.local` 填 `SEARCH_LLM_API_KEY`（默认通义千问，见 `.env.example`）。可以在「每日自动更新」里关掉

**投递进度**（左侧「投递进度」）
- 看板分 5 列：已投递、测评/笔试、面试中、Offer、已结束；点卡片看时间线、改状态、写备注、手动加事件
- 同步邮件：在 `.env.local` 填好邮箱和授权码（见 `.env.example`）后点「同步邮件」
  - 先只看发件人和标题，判断是招聘邮件才读正文；只保存标题、发件人、摘要和识别结果
  - 本地规则识别邮件类型（投递确认、测评、笔试、面试、HR面、Offer、未通过）、公司、时间、链接，并匹配到对应的投递（兼容北森、Moka 等招聘系统代发的邮件）
  - 规则拿不准的邮件，可以勾选「用模型补充识别」，人名等敏感信息脱敏后再发给模型
  - 「投递成功」类邮件自动加进投递列表，不用确认；其他邮件由你确认后才会写进时间线、推进状态（「确认今天的 N 封」可一键确认当天收到的）；状态只往前推进，Offer 和未通过直接生效
- 同一家公司只保留一条投递记录：投了多个岗位会合并成一条，岗位名拼在一起
- 看板每列按时间从近到远排：有下一场测评、笔试、面试的排在前面
- 未来 30 天日程：测评、笔试、面试，加上岗位库里有明确截止日期、这家公司还没投过的网申截止（收藏的或属于「我的方向」的），按时间从近到远；「导出到日历」下载 .ics，可导入手机日历、Outlook、飞书日历（面试提前 30 分钟提醒，网申截止前一天提醒）
- 日程每行前面可以打勾划掉（网申截止打勾 = 投了或决定不投），首页简报不再提醒；「待跟进」里点「查过了」，14 天内不再提醒

## 面试准备

确认一封面试邮件后自动开始准备（也可以在「我的投递」里手动点），打开 `/prep/<投递id>`：
- **面试准备稿**：
  - 一、简历深挖：最该讲的 2~4 段经历，每段备好追问（做了什么 / 数字口径和对照 / 个人贡献 / 重来会怎么改），再加 JD 要求里你素材证明不了的风险点和准备动作
  - 二、公司业务：最新情况（带来源）、团队在做什么的推断和拆解公式、业务题和答题思路
  - 三、表达：为什么选这个岗位、1 分钟自我介绍主线、反问
  - 追问里的数字核对过出自你的素材；业务事实必须有来源，数字必须出现在调研原文里
- **深度调研**：在后台自动跑（复用调研 agent），一次只跑一个，面试在 24 小时内的预算减半；同一公司同一岗位 14 天内做过的直接复用，JD 变了只重写报告。做完后自动补上准备稿的「二、公司业务」，业务题也会并进模拟面试
- **JD**：没有关联岗位时联网找，届别比你投的早、校招和实习对不上的网页会被排除，发布时间较早的会提示核对；可以随时贴真实 JD 重新准备
- **模拟面试**：一问一答，每题点评并追问一次

## 调研 agent（面试准备的自动深度调研在用）

需要在 `.env.local` 配置 `LLM_API_KEY`（DeepSeek）和 `SEARCH_LLM_API_KEY`（通义千问联网搜索，和岗位库的联网搜索共用）。原来独立的「深度调研」页面已经去掉，调研只在确认面试后自动跑，结果显示在面试准备页。

**联网搜索的来源**：用千问的 DashScope 原生接口（`enable_source`），只取搜索结果的原始链接、标题和网站名；千问顺带生成的回答不用，结论只能来自 agent 自己读过的网页原文。千问搜索不能限定网站和时间范围：渠道和「近一年 / 近一个月」写进搜索词，结果再按域名过滤；搜索结果没有摘要，发布日期只在链接里带日期时显示。

**两个阶段**
1. **调研 agent（只接触公开信息）**：拿到公司名、岗位、JD 和参照公司名，拿不到你的素材库。模型自己决定下一步：
   - `web_search`：联网搜索（可指定渠道：官网、财报与交易所披露、研究机构、行业媒体、公众号、用户论坛、招聘广告；近一年动态用 oneYear）
   - `read_page`：读网页正文（公众号文章、PDF 也能读）
   - `record_finding`：记录一条发现，必须附原文摘录
   - `finish`：结束
   约束（harness）：最多 24 步、12 次搜索、10 次阅读；摘录必须出现在已读网页原文里，否则驳回；搜索词里出现素材库敏感词会被拦截；每条来源按域名标渠道和可信度（官方 > 权威第三方 > 一般媒体 > 论坛/自媒体）；每一步都记录在「调研过程」里
2. **生成报告（不联网）**：调研发现 + 你的经历卡片（只含简历原句，先在本地脱敏；标了「仅本地」的不发）→ 一次模型调用。生成后在本地核对：经历证据必须是卡片原句；公司事实必须引用真实存在的来源编号，没有来源的标「无来源」

**报告结构**：岗位画像（JD 三大能力 ↔ 我的经历证据、匹配度、缺口）/ 业务条线与主要产品 / 深入了解的渠道（官方、第三方、第一手）/ 竞品对比（以我实习的产品为参照：商业模式、业务位置、目标用户和市场、近一年动态、竞争格局、增长和运营，附 SWOT、可迁移经验、面试观点）/ 待补功课。每章有结论。

**参照经历**：默认由模型从经历卡片里挑和岗位业务最接近的一段（卡片先脱敏），也可以手动指定。

## 数据存放位置

```
data/
  library.json        卡片、资料清单、敏感词设置
  tracker.json        岗位库、投递记录、招聘邮件
  research/<id>.json  每份面试调研（过程、来源、发现、报告）
  memory.json         AI 的长期记忆：滑动记录、岗位偏好、写作偏好、你补充的事实、简历抬头
  native/jd/          抓到的 JD
  native/company/     公司速览缓存
  native/apply/       每个岗位的定制简历和对话
  native/prep/        每场面试的准备材料和准备稿
  embeddings.json     向量缓存（素材 90 天没用到自动清掉，JD 类查询只留最近 300 条）
  sources/<id>.txt    每份资料解析出来的纯文本
```

`data/` 已经写进 `.gitignore`，不会被提交到代码仓库。想备份，直接复制这个文件夹就行。
