## 通用能力 / 组件能力 / 平台补充（2026-09-14）

以京东校园招聘暴露的问题为样本推进分层，**没有新增京东域名适配器**。三个层次的职责如下：

| 层次 | 职责与边界 | 实现入口 |
| --- | --- | --- |
| 通用能力 | 发现字段、识别分区/经历、白名单匹配、保留已有值、校验和报告；不理解公司业务 | `scanner.ts`、`sections.ts`、`executor.ts`、`background/planner.ts` |
| 组件能力 | 根据控件结构发现/认领元素，声明日期精度，读取已选值，操作并验证；不决定履历对应关系，不点击添加经历 | `content/components/types.ts`、`registry.ts`、`ant-mobile.ts`；既有操作实现在 `content/controls/` |
| 平台补充 | 限定真实表单范围、提供字段/分区/经历和已验证组件变体提示；保留平台专有的有限新增流程 | `content/adapters/` |

这是渐进拆分：既有 Moka / Phoenix / ATSX 日期和地区变体通过平台提示接入统一组件执行入口，保留其历史类型名；原生控件和普通 ARIA 下拉仍走通用处理。部分旧平台的标签/视觉外壳兼容代码仍在 DOM 工具中，没有宣称完成所有历史代码的迁移。新组件无需新增公司适配器，也不需修改通用执行器的分派分支。

本轮新增能力：

- 按完整的短分区标题识别没有标准 heading 的页面；支持“标题装饰容器 + 相邻内容”的结构，以后续标题为边界。未知的校园、专利等标题也作为边界，不继承前一个已知分区。原有明确标题优先，避免影响 Moka 动态新增。
- 发现 Ant Mobile `am-list-item` 的非原生选择器。组件自己读取 `.am-list-content` 标签和 `.am-list-extra` 值，避免把已选值混进字段标签、避免重复扫描原生输入框。
- 支持经结构核验的单列滚轮与中文年/月/日三列滚轮：通过鼠标拖动事件、等待滚轮选中状态、明确确认、回读和最终复查完成填写，不访问 React 私有状态，不直接改展示文本。
- 仅操作本轮新打开的唯一弹层。禁用、用户已有值、重复候选、选择中原值变化、页面拒绝回显均不会被当作成功；失败时取消自己打开的可识别滚轮。
- 短标签与自定义控件同行但没有可操作元素时，补充待处理报告；空白经历分区只有“添加”按钮时给出先手动添加再重扫的提示。报告仍是已发现字段的统计，**不是整个网站的完整覆盖率**。
- 新增“是否最高学历”“专业成绩排名”通用别名；敏感字段、声明、附件和最终提交的边界保持不变。

验证样本是 `demo/component-controls.html`：不含站点适配标记，所有内容虚构；包含相邻分区与标准 fieldset 两种布局。其滚轮是独立的行为仿真（选项点击无效、拖动后延迟选中、确认才更新、确认后替换 DOM 节点），用于验证生产扩展完整消息链路。**本地仿真通过不等于新版已经在京东实页填写成功**，真实页面尚需重载新版后复验。

本轮仍保留人工处理：多列地区级联、站点定制的列表/多选/学校搜索弹窗、非 List.Item 的自定义日期范围、未验证的新组件变体。只有年月的资料不会自动补一个“日”；通用模式不自动添加经历、不按顺序猜多段履历。可先在网页添加经历，再重新扫描并在有歧义时手动绑定整组。

当时验证：`npm run verify` 通过，111 个单元测试、52 个真实扩展端到端测试（含 8 个新增组件用例）；诊断包构建通过。生产包 610.2 KiB，内容脚本 v12，权限未增加。当前合并验证数据见下方传音小节。

**这次测试发现并修复的问题**（都已加回归测试）：

1. **标签完全解析不出来**（致命）。Moka 不用 `<label for>`，而是
   `<div class="field"><div class="filed-title-xxx">姓名</div><div>…<input></div></div>`，
   标签在控件祖先的兄弟节点上。原来的实现只看「前置兄弟」和「父元素内的 label」，
   导致 51 个字段里 47 个标签为空、全部 `NO_MATCH`。现在改为从控件逐层向上查找**不含任何控件**的
   前置兄弟，取最近的一个。
2. **伪下拉框会造成假成功**（致命）。29 个「输入框」其实是自定义下拉的壳。修复标签解析后，
   「最高学历」会被匹配上并写入文本——外观变了，网站状态没变，扩展却会报成功。
   第一轮先通过 `请选择` 类占位符与 `select`/`dropdown` 类容器把它们识别出来并拒绝写入；
   第二轮改为真正支持（见下方「第二轮新增」），日期选择器仍然拒绝操作。
3. **分区标题识别不到**。标题是 `<div class="block-title-xxxx">`，不是 `h1`–`h6`/`legend`，
   导致 9 个分区一个都没识别出来、多段经历无法绑定。现在支持这类 class 命名。
4. **「工作经历」和「实习经历」互相抢记录**。两块都映射到模型里唯一的 `internships`，
   结果两边都填不了。现在同时存在时只把写着「实习」的那块当 internships，另一块如实报告。
5. **岗位候选被瞎猜**。页面标题「搜狐 - 校园招聘」被切成「岗位=搜狐 / 公司=校园招聘」。
   现在只有当某一边明显像岗位名时才给候选，否则不给。
6. **锁定与敏感字段没有说明**。现在分别提示「网站锁定了这个字段」「这类敏感信息不会自动填写」，
   而不是笼统的「需要你自己确认或操作」。

**第二轮新增：支持没有 ARIA 的自定义下拉。**
Moka 的下拉没有 `role`、没有 `aria-controls`，点开后才把选项渲染进**控件自己的 Dropdown 容器**里
（`div.sd-Menu-content-item > div.option-label`）。现在的做法与 ARIA combobox 完全一致，
只是列表靠结构而不是 `aria-controls` 找到：点开 → 在控件自己的容器内找选项 → 精确唯一匹配 → 点击 → 回读确认。
可搜索的下拉（学校名称、专业名称）会先把要选的值输进去过滤，再点选项；没找到就把输入框恢复原样。

在真实页面上做过**只读探测**验证这条链路：展开「学历」下拉，在控件自己的容器里发现 9 个选项
（本科/硕士/博士/高中/大专/中专/初中及以下/MBA/其他），按等价词表唯一命中「硕士」，
全程输入框值未变、未点击任何选项。**「点击选项 + 回读确认」这一步是在本地复刻页 `demo/ats-style.html` 上验证的。**

**第三轮新增：四段式年月范围与准确扫描预览。** Moka 的经历日期不是日历，而是四个独立下拉，
只通过占位符形成 `年、月、年、月` 序列。现在仅在同一局部容器内严格命中这个完整序列时，
才按 DOM 顺序绑定为开始年/月、结束年/月。真实页展开年份菜单后还发现它没有 `option-label`，
只有 `sd-Menu-content-item-*`；选项查找已兼容该结构，并继续限定在控件自己的容器内。
实际点选与回读用本地复刻页验证；真实页只展开、读取并关闭菜单，值未变化。

扫描预览现在把所有 51 个字段完整列出：11 个显示「可自动填写」，40 个显示「待处理」，
不再把可填字段排除在“本轮共 N 个字段”之外。「最高学历」也会从教育记录中确定为唯一值。

**尚未验证的部分**：扩展在这个页面上的**实际写入**没有跑过——只验证了扫描、匹配与选项发现。
要完整验证，需要导入你自己的真实履历，在该页面点击工具栏图标后先「扫描页面」核对结果，再决定是否填写。

**已知能力缺口**（不是 bug，是 P0 模型的边界）：

- 履历模型没有「工作经历」（全职）、薪资、获奖经历，这些字段只能手动填。
- 页面上经历位置少于履历条数时不会猜，也不会自动点击网站的「添加」按钮（通用模式不点任何未知按钮）。
  现在结果页会为每一组这样的字段给出「这一组对应哪一条经历？」的选择器，选定后整组一次填写。

## 如何验证一个新网站

```bash
npm run diagnose
```

这会构建只读诊断包并在 `http://127.0.0.1:4174` 提供。然后在招聘页面的控制台里：

```js
const r = await fetch('http://127.0.0.1:4174/applykit-diagnose.js'); (0, eval)(await r.text());
console.table(window.__applykitDiagnose().fields);
```

它运行的是扩展真实的扫描与匹配代码，只读 DOM，不写入任何字段，报告里不含已填内容（记录名称只报「有/无」）。

拿到报告后：

1. 记录：网站与页面类型、期望行为、实际行为、脱敏后的控件结构。
2. 用虚构数据在 `demo/` 里构造一个最小复现页面，加回归测试。
3. 再改匹配器或写适配器，跑 `npm run verify`。
4. 把结果补进上表；登录、验证码、无法重复访问等限制如实写明。
