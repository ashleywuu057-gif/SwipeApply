# 安全策略

## 支持范围

安全修复面向默认分支和最新公开版本。旧版本通常不会单独维护，请先确认问题在默认分支仍可复现。

## 私下报告漏洞

请使用 GitHub 仓库的 **Security → Report a vulnerability** 提交私密报告。仓库创建后应启用 Private vulnerability reporting。

如果该入口暂时不可用，可以创建一个不含漏洞细节的公开 Issue，请维护者提供私密联系方式。不要在公开 Issue、讨论或截图中提供：

- 真实履历、手机号、邮箱、学号或证件信息；
- 招聘网站账号、Cookie、令牌或带身份参数的页面地址；
- 可以直接利用漏洞的完整步骤或载荷。

报告中请包含受影响版本、影响范围、已脱敏的复现步骤和建议修复方式。维护者确认修复并给出披露时间后，再公开技术细节。

## 重点安全边界

以下行为应视为安全问题：

- 在用户未通过工具栏授权时访问招聘页面；
- 将履历或网页字段值发送到外部服务；
- 绕过敏感字段白名单和专用站点精确绑定，或绕过声明、附件、验证码及最终提交的人工确认；
- 字段映射保存具体个人信息或可执行代码；
- 生产构建新增未说明的主机、Cookie、历史记录或调试权限。
