# 贡献指南

感谢你改进 ApplyKit。提交代码前，请先阅读 [PRIVACY.md](PRIVACY.md) 和 [SECURITY.md](SECURITY.md)。

## 开发环境

项目要求 Node.js `^22.12.0 || ^24.0.0 || >=26.0.0`。

```bash
npm ci
npx playwright install chromium
npm run verify
```

`npm run verify` 会依次运行类型检查、单元测试、生产构建和真实扩展端到端测试。

## 提交原则

- 不要提交真实履历、投递记录、招聘账号信息、页面 Cookie、访问令牌或未经脱敏的截图和 DOM。
- 测试资料必须明确标记为虚构，并使用 `example.com`、保留号段或本地地址。
- 不要扩大生产权限，除非变更本身充分说明用户价值、数据边界和更小权限方案为何不可行。
- 保持“不自动提交”边界：附件、声明、验证码和最终提交由用户操作。
- 不确定或有歧义的字段应进入待处理，不能为了提高填写数量而猜测。

## 新增或修改站点适配器

先判断缺口属于哪一层：字段发现、标签/分区归属和校验放在通用层；可复用控件的发现、交互与回读放在 `src/content/components/`（既有操作函数位于 `controls/`）；只有平台语义、表单边界和明确业务例外才放在 `adapters/`。不要因为一家公司的页面填写不足，就默认新增域名适配器。

组件驱动不得决定履历来源、按顺序猜经历或点击新增按钮。新增组件需要不同布局的回归、未支持变体的安全退出、已有值/禁用保护，以及页面事件状态和回读验证；本地仿真通过与实页验证必须分别记录。

每个站点适配必须同时包含：

1. 明确且足够窄的页面匹配条件；
2. 不含真实个人信息的本地复刻页面；
3. 覆盖扫描、填写、回读和重复运行的 Playwright 用例；
4. 对不支持控件和歧义选项的安全退出行为；
5. 在 `docs/SITE-COMPATIBILITY.md` 中记录经过验证的能力和限制。

通用适配器不应猜测“新增经历”按钮，也不应在全页范围搜索下拉选项。

## Pull Request

- 说明具体问题、触发页面结构和修改后的行为。
- 列出执行过的验证命令；若跳过某项测试，请说明原因。
- 标明是否影响浏览器权限、数据模型、迁移、隐私边界或现有站点适配器。
- 一个 Pull Request 尽量只解决一个清晰问题。
